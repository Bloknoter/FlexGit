# FlexGit

Async C# git API built on the real `git` command line.

Because every operation runs real git, everything a terminal can do also works here:
- **Git LFS**: pull, checkout and push transfer real content; locks are supported.
- **Git Credential Manager**: browser/OAuth sign-in for GitHub, GitLab, Azure DevOps and others.
- **SSH**, **hooks**, `.gitattributes` filters and `includeIf` configs.
- **Any other git command** through `RunRawAsync`.

The library targets **.NET Standard 2.1** with C# 9 and has no dependencies.

## Requirements

- A runtime with .NET Standard 2.1: .NET Core 3.0+, .NET 5+ or Mono 6.4+.
- **Git 2.32+**. [Git for Windows](https://git-scm.com/download/win) includes Git LFS and Git Credential Manager. Git is looked up on `PATH`, then in the default install folders. To use another location, set `GitOptions.GitExecutablePath`.
- Developed and tested on Windows x64. The code is cross-platform, but macOS and Linux aren't tested yet.

## Install

Download `FlexGit.dll` (and `FlexGit.xml` for IntelliSense docs) from the [latest release](https://github.com/Bloknoter/FlexGit/releases/latest) and reference it. Or add `src/FlexGit/FlexGit.csproj` to your solution.

### If using in a Unity project

Unity 2021.3 or newer. In **Package Manager**, choose **+ → Add package from git URL…** and enter:

```
https://github.com/Bloknoter/FlexGit.git#upm/v2.0.0
```

Or add it to `Packages/manifest.json`:

```json
"com.bloknoter.flexgit": "https://github.com/Bloknoter/FlexGit.git#upm/v2.0.0"
```

To update, change the tag to a newer `upm/vX.Y.Z` (see [Releases](https://github.com/Bloknoter/FlexGit/releases)). The package is Editor-only: it compiles into a `FlexGit` assembly for Editor tools, never into builds.

The `upm` branch is generated by the Release workflow from `src/FlexGit` (sources + `package.json` + `.meta` files). Don't edit it by hand.

## Quick start

```csharp
using FlexGit;

var repo = await GitRepository.OpenAsync(@"C:\Projects\MyGame");   // any folder inside the repository

var status = await repo.GetStatusAsync();
Console.WriteLine($"{status.Branch}: {status.Entries.Count} changes, ahead {status.Ahead}, behind {status.Behind}");

await repo.Index.StageAllAsync();
var commit = await repo.CommitAsync("Rework level 3 lighting");
if (commit.Status == CommitStatus.NothingToCommit) { /* ... */ }

var pull = await repo.PullAsync(progress: new Progress<GitProgress>(p => Console.WriteLine($"{p.Phase} {p.Percent}%")));
if (pull.Status == PullStatus.Conflicts)
{
    foreach (var conflict in await repo.Conflicts.ListAsync()) Console.WriteLine(conflict.Path);
    // Resolve (see "Resolving conflicts" below), then repo.ContinueMergeAsync()
}

var push = await repo.PushAsync();                             // the first push of a branch sets its upstream
if (push.Status == PushStatus.Rejected) { /* someone pushed first: pull, then push again */ }
```

Every method is async and takes a `CancellationToken`. Long-running operations also take an `IProgress<GitProgress>`.

### Resolving conflicts

When a merge, pull, rebase or stash pop stops with conflicts, `repo.Conflicts` shows what conflicted and resolves it:

```csharp
var overview = await repo.Conflicts.GetOverviewAsync();          // Operation (Merging, Rebasing, ...) + every unmerged file
foreach (var info in overview.Files)
{
    if (!info.CanResolveHunks)
    {
        // Binary, deleted on one side, or markers already removed by hand: resolve the whole file.
        await repo.Conflicts.TakeTheirsAsync(new[] { info.Path });   // or TakeOursAsync / MarkResolvedAsync
        continue;
    }

    var file = await repo.Conflicts.GetFileAsync(info.Path);     // hunks + the text around them (file.Segments)
    foreach (var hunk in file.Hunks)
        Console.WriteLine($"lines {hunk.StartLine}-{hunk.EndLine}: {hunk.GetChoiceLabel(ConflictChoice.OursThenTheirs)}");
        // hunk.Ours / hunk.Theirs (and hunk.Base with merge.conflictStyle=diff3); labels such as "HEAD" / "feature"

    var result = await repo.Conflicts.ResolveAsync(file, new[]
    {
        new ConflictHunkResolution(0, ConflictChoice.Ours),            // "Use HEAD"
        new ConflictHunkResolution(1, ConflictChoice.TheirsThenOurs),  // "Use feature then HEAD"
        ConflictHunkResolution.Custom(2, "hand-written line\n"),
    });
    // Resolved: no markers left, file staged. PartiallyResolved: unlisted hunks keep their markers.
    // FileChanged: the file was edited after GetFileAsync; nothing was written, read it again.
}
await repo.ContinueMergeAsync();                                  // or repo.Rebase.ContinueAsync()
```

- `ResolveAsync(file, ConflictChoice.Theirs)` applies one choice to every hunk. `file.GetResolvedText(...)` previews the result without writing.
- Choosing `Ours` for every hunk keeps the other side's changes that merged cleanly. `TakeOursAsync` takes our whole version of the file instead.
- `RestoreConflictAsync(paths, ConflictMarkerStyle.Diff3)` rewrites a still-unmerged file with all its original hunks, discarding edits made to it since.
- During a rebase, "ours" is the branch you rebase onto and "theirs" is your commit. After a conflicted stash pop the stash is kept, so drop it after resolving.
- Hunks come from the conflict markers in the working-tree file, so manual edits are picked up. The `conflict-marker-size` attribute is respected. Text that isn't UTF-8 is copied byte for byte (custom text is written as UTF-8).

### Results, errors, cancellation

- **Operations** (commit, switch, pull, push, merge, rebase, stash, clone and others) return a result object with a `Status` enum, a `Message` and `Succeeded`. Expected outcomes are statuses, not exceptions. Examples: `PullStatus.Conflicts`, `PushStatus.Rejected`, `CommitStatus.NothingToCommit`, `SwitchStatus.LocalChangesWouldBeOverwritten`.
- **Queries and simple changes** throw `GitCommandException` on failure. Its `Kind` (`GitErrorKind`) classifies the failure: `AuthenticationFailed`, `NetworkError`, `NotARepository`, `IndexLocked` and so on. `Error.StandardError` holds git's output.
- **Cancelling** kills the git process tree and throws `OperationCanceledException`.
- Operations never discard local changes unless you ask, for example with `SwitchOptions.DiscardLocalChanges` or `DiscardAsync`.

### Threading

FlexGit never blocks a thread while git runs and uses `ConfigureAwait(false)` internally, so it is safe to await from a UI thread. Your own code after `await` resumes on your synchronization context as usual, and a `Progress<T>` created on a UI thread reports on that thread.

Calls on the same repository run one at a time, even across `GitRepository` instances, which avoids `index.lock` errors.

### Logging

Set `GitOptions.Logger` to receive every git command line (credentials in URLs are redacted) and its outcome.

### Git LFS

LFS works automatically through git's filters and hooks. Call `await repo.Lfs.EnsureInstalledAsync()` once per repository. It checks that the LFS filters and the **pre-push hook** (which uploads LFS objects) are installed, and runs `git lfs install --local` if they aren't.

The locking commands need an LFS server with the locking API, such as GitHub or GitLab.

### Credentials

FlexGit never asks for passwords. Git asks its credential helper, which on Windows is Git Credential Manager and shows its own sign-in window. Prompts on the terminal are disabled, so an operation without credentials fails with `GitErrorKind.AuthenticationFailed` instead of hanging.

### Anything else

```csharp
var result = await repo.RunRawAsync("log", "--graph", "--oneline", "-20");
Console.WriteLine(result.StandardOutput);
```

## Development

```
FlexGit.sln              .NET solution (Visual Studio / Rider)
src/FlexGit/             the library (netstandard2.1, C# 9)
tests/FlexGit.Tests/     MSTest: unit tests + integration tests against real git in temp folders
.github/workflows/       CI (every push except main/upm, pull requests) and Release (main)
.github/upm/             package template and scripts for the generated upm branch (for Unity projects)
```

- **Build and test:** `dotnet test FlexGit.sln -c Release`. The tests need git 2.32+ and git-lfs on `PATH`. They use isolated git configs in temp folders and don't touch your global git settings.
- **Language level:** the library stays on C# 9 and .NET Standard 2.1 APIs (no records, `init`, `ProcessStartInfo.ArgumentList` or System.Text.Json). The build enforces this. If using in a Unity project, that's what Unity 2021.3+ can compile.
- **If using in a Unity project:** `bash .github/upm/build-package.sh <output-dir>` writes the package that a release would publish. Reference that folder with `"com.bloknoter.flexgit": "file:<output-dir>"` to try unreleased changes.

## Releasing

1. Bump `<Version>` in `src/FlexGit/FlexGit.csproj`, following [SemVer](https://semver.org).
2. Add a `## [X.Y.Z] - YYYY-MM-DD` section to `CHANGELOG.md`.
3. Merge to `main`. The **Release** workflow:
   - runs the tests;
   - creates tag `vX.Y.Z` and a GitHub Release with that CHANGELOG section and `FlexGit.dll`, `FlexGit.xml` and `FlexGit.pdb` attached;
   - for Unity projects, builds the package, commits it to the `upm` branch and tags it `upm/vX.Y.Z`.

   If the version already has a tag, nothing happens. A version with a suffix, such as `2.1.0-preview.1`, becomes a pre-release.
